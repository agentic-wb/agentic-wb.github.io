처음 사용하는 Workbench

내 자료를 고르고, AI에게 일을 맡기고, 근거를 확인해 결과를 남깁니다.

이 매뉴얼을 읽는 두 가지 방법

  • 업무 사례로 배우기: 지금 겪는 상황과 가까운 사례를 골라 준비 자료부터 결과 확인까지 따라갑니다. 여러 자료를 모아 고객 메일에 답하기부터 시작해도 좋습니다.
  • 기능으로 찾아보기: 버튼이나 기능을 알고 있다면 기능 색인과 용어 찾기에서 바로 찾습니다. 각 사용법에는 해당 기능을 쓰는 업무 사례도 연결되어 있습니다.

HTML에서는 상단의 업무 사례 / 기능 찾기와 검색창을 사용하세요. Obsidian에서는 문서 링크를 누르거나 파일 검색으로 WB_F02처럼 항목 번호를 찾으세요. 검색어는 ‘메일’, ‘PDF’, ‘분기’, ‘복사’, ‘오류’처럼 평소 쓰는 말로 입력해도 됩니다.

먼저 알아둘 세 가지

  • Vault는 Obsidian에서 연 문서 폴더입니다. Session은 한 가지 일을 이어가는 대화입니다.
  • Sources는 이번 요청에 참고하도록 선택한 자료입니다. 탭을 열었다는 사실과 Source로 첨부했다는 사실은 다릅니다. 전송 전에 Source 목록을 확인하세요.
  • Workbench 사용권과 AI 계정은 별개입니다. 실제 사용할 AI 연결과 사용할 자료를 준비합니다. 시작하기: 설치·사용권·AI 연결

첫 실습: 진행 상황에서 답변 초안 만들기

이 매뉴얼의 연습자료 폴더에는 실제 고객 정보가 없는 가상 문서가 있습니다. 아래 예시는 연습용이며 실제 업무 결과가 아닙니다. HTML만 받았다면 각 연습자료에서 연습자료 저장 (.md)을 눌러 내려받은 뒤 사용하는 Obsidian 문서 폴더에 넣으세요. HTML 안의 문서 링크는 내용 미리보기이고, Add to source는 Obsidian 파일 메뉴에서 사용합니다.

  1. Obsidian에서 연습자료의 프로젝트 현황과 고객 메일 파일을 엽니다.
  2. 두 파일을 각각 오른쪽 클릭하여 Add to source를 선택합니다. Source 목록에 두 파일이 있는지 확인합니다. 관련 없는 자료가 있다면 ×로 제외합니다. Sources: 참고 자료 선택과 제외
  3. 입력창 아래 모델 메뉴에서 사용할 모델을 선택합니다. 모델명 자체를 클릭하면 그 모델의 Effort는 Auto가 됩니다. 모델·Effort·사용량 선택
  4. 아래 요청을 붙여 넣고 Windows에서는 Ctrl+Enter, macOS에서는 Cmd+Enter로 실행합니다. 요청 작성·보완·즉시 실행
  5. 답변의 숫자와 일정을 자료와 대조한 뒤 노트로 저장으로 보관합니다. 결과 저장·복사·다른 앱에서 이어가기

고객 질문마다 현재 답할 수 있는 내용과 확인이 필요한 내용을 구분해주세요.

기능 안내 · F01

시작하기: 설치·사용권·AI 연결

Workbench 사용권을 확인하고 실제로 사용할 AI 계정을 연결합니다.

어디서 사용하나요?

Obsidian 설정의 Workbench 항목과 Workbench 상단 정보 아이콘에서 연결·사용권 상태를 확인합니다. Obsidian 명령 팔레트에서 Workbench: Open workbench로 작업창을 열 수 있습니다.

사용 순서

  1. Workbench와 지원되는 데스크톱 Obsidian을 설치하고 사용할 문서 폴더를 엽니다. 0.19.50의 최소 Obsidian 버전은 1.15.0입니다.
  2. 사용권 화면에서 발급받은 키로 인증하고 유효 상태를 확인합니다.
  3. 연결 설정에서 사용할 Codex·Antigravity·Claude 연결을 확인합니다. 필요한 로그인은 해당 앱에서 직접 완료합니다.
  4. 연결 점검 후 모델 메뉴에서 실제 사용할 수 있는 모델을 선택합니다. 모델·Effort·사용량 선택
  5. 처음 사용하는 Workbench의 짧은 연습으로 자료 첨부와 답변을 확인합니다.

확인과 문제 해결

Workbench 라이선스가 AI 모델 사용권·사용량을 대신하지 않습니다. 다른 앱에서 로그인되어 있어도 Workbench가 그 앱의 모든 도구나 계정을 그대로 상속하는 것은 아닙니다. 연결 점검 성공과 개별 메일·웹 서비스 접근 성공도 구별합니다. 키 재발급·갱신 후에는 사용권 화면에서 새 상태를 확인하고 기존 Session을 다시 엽니다.

기능 안내 · F02

Sources: 참고 자료 선택과 제외

AI가 이번 요청에 사용할 파일을 눈으로 확인합니다.

어디서 사용하나요?

입력창 위 Sources, +, 열린 탭과 파일 오른쪽 클릭 메뉴의 Add to source를 사용합니다.

사용 순서

  1. 파일을 오른쪽 클릭해 Add to source를 선택하거나, +에서 지원되는 파일·폴더 경로를 추가합니다.
  2. 여러 열린 문서를 쓰려면 열린 탭을 켭니다. 같은 파일의 중복 탭은 중복 첨부되지 않습니다.
  3. Source 이름과 개수를 확인하고 +N개를 펼쳐 전체 목록을 봅니다. 필요 없는 항목은 ×로 제외합니다.
  4. 전송 전에 파일이 저장되어 있고 필요한 부분을 포함하는지 확인합니다.

알아둘 동작

폴더 선택은 기본적으로 하위 Markdown을 중심으로 묶습니다. 다른 형식은 파일을 직접 지정해 포함 여부를 확인하세요. 외부 파일은 읽기 자료이며 자동으로 Vault로 복사되거나 수정 권한이 생기지 않습니다. ZIP 같은 미지원 경로를 입력창에 붙이면 텍스트로 남습니다. 경로가 보이는 것만으로 파일이 첨부된 것은 아닙니다.

Sources 변경은 다음 요청에 적용됩니다. 현재 목록에서 빼도 이전 대화에 전달한 맥락이 지워지지는 않습니다. 이전 맥락을 쓰지 않을 작업은 새 대화로 시작하세요. 한도 오류가 나면 필요한 자료로 좁히거나 화면에서 제공하는 이번 요청의 한도 조정을 검토합니다.

기능 안내 · F03

PDF·이미지·외부 파일 참고하기

문서 형식과 실제 읽힌 범위를 확인하면서 질문합니다.

사용 순서

  1. 지원되는 PDF 또는 이미지 파일을 Add to source나 +의 경로 추가로 선택합니다. Sources: 참고 자료 선택과 제외
  2. PDF는 질문할 페이지·표·항목을 요청에 함께 적습니다. 이미지의 글자가 작으면 읽을 부분을 더 선명하게 준비합니다.
  3. 답변에 문서명·페이지 또는 근거 위치를 함께 달라고 요청합니다.
  4. 중요한 숫자와 표는 원문을 열어 대조합니다.

범위와 주의점

PDF는 텍스트 추출과 일부 페이지 이미지로 전달됩니다. 전체 페이지의 모든 도표가 이미지로 전달되는 방식은 아닙니다. 암호화된 PDF는 열 수 있는 사본이 필요하고, 큰 스캔 문서는 나누어야 할 수 있습니다. 스캔 페이지 이미지에는 수량·크기 제한이 있습니다.

외부 경로와 클라우드 동기화 파일은 이 PC에서 실제로 읽을 수 있어야 합니다. 표시된 ‘찾을 수 없음’이나 접근 오류를 해결하지 않고 분석을 완료한 것으로 간주하지 마세요. 전용 뷰어로 열 수 있는 파일과 AI Source로 지원되는 파일은 서로 다를 수 있습니다.

기능 안내 · F04

요청 작성·보완·즉시 실행

목적, 자료 범위, 결과 형태를 적고 원하는 방식으로 실행합니다.

사용 순서

  1. 무엇을 할지 + 어떤 자료를 쓸지 + 어떤 결과를 원하는지를 적습니다. 예: ‘첨부 메모로 결정 사항과 담당자별 할 일을 표로 정리해주세요.’
  2. 필요한 Source와 모델을 확인합니다.
  3. 요청을 보완해 진행하려면 입력창의 일반 Enter 흐름을 사용하고 제시된 확인 질문·개선 요청을 검토합니다.
  4. 작성한 요청을 바로 실행하려면 Ctrl+Enter, macOS는 Cmd+Enter를 사용합니다. 이는 요청 보완 단계를 건너뛰지만 사용권·사용량·자료 검사를 건너뛰지는 않습니다.
  5. 여러 줄은 Shift+Enter로 입력합니다.

답변을 기다리는 동안 다음 요청 준비

답변 중에도 입력창에 다음 요청을 작성할 수 있습니다. Enter, Ctrl+Enter / Cmd+Enter 또는 대기 추가 아이콘을 누르면 같은 Session의 대기 목록에 저장되고, 현재 답변이 끝난 뒤 순서대로 실행됩니다. 중지 버튼은 현재 실행을 멈춥니다.

현재 작업의 방향을 바꾸려면 진행 중 지시 기능을 사용합니다. Codex는 진행 중인 작업에 지시를 전달하며, 지원하지 않는 연결에서는 화면에 안내된 중단 후 이어가기 흐름을 사용합니다.

오류, 사용자가 중지한 경우, 앱을 다시 연 경우에는 대기 요청이 자동으로 실행되지 않습니다. 목록을 확인하고 재개하세요. 대기 요청은 현재 Session의 Source와 모델을 사용하므로 실행 전에 다시 확인합니다.

확인과 문제 해결

답변 생성 중인지, 질문에 대한 답을 기다리는지, 오류로 멈췄는지 상태와 작업 내역을 확인합니다. 진행 문구만 있고 최종 결과가 없으면 완료로 간주하지 않습니다. 한글 조합 중인 Enter는 입력 확정에 사용될 수 있습니다. 입력 초점이 요청창에 있는지 확인하고 필요한 경우 전송 버튼을 사용하세요.

인용 코멘트 편집기의 Enter는 코멘트 확인이며 요청 실행이 아닙니다. 답변 일부를 인용해 수정 요청

모델·Effort·사용량 선택

현재 작업에 쓸 모델과 추론 수준을 고릅니다.

어디서 사용하나요?

입력창 아래 모델명을 누르면 위로 펼쳐지는 메뉴가 열립니다. 현재 선택 모델 위치에서 선택을 이어갈 수 있습니다.

사용 순서

  1. 모델 메뉴에서 검색하거나 목록을 살펴봅니다.
  2. 모델명 자체를 클릭하면 해당 모델의 Effort가 Auto로 선택됩니다.
  3. 특정 수준이 필요할 때만 옆의 하위 메뉴에서 지원되는 Effort를 고릅니다.
  4. 메뉴 최상단 Auto는 모델 선택을 맡기는 항목입니다. 특정 모델의 Effort Auto와 구별하세요.
  5. 사용량 표시를 펼쳐 연결·계정·남은 한도·초기화 시점을 확인합니다.

알아둘 동작

작업 승인 방식과 앱 접근 권한

실행 범위에 맞게 승인 방식을 정하고 실제 요청을 확인합니다.

어디서 사용하나요?

입력창 아래 작업 승인 방식 메뉴에서 선택합니다. 이 메뉴는 특정 모델 이름에만 종속된 설정이 아닙니다.

선택 항목

  • Ask for approval: 실행기가 정한 경계에서 사용자 확인을 요청하는 방식입니다.
  • Approve for me: 지원되는 실행기가 위험을 검토하고 필요할 때 확인을 요청합니다. 미지원 상황에서는 직접 확인이 필요할 수 있습니다.
  • Full access: 파일·인터넷 접근 범위가 넓어집니다. 작업에 필요한 범위를 이해하고 선택합니다.
  • Custom: 선택한 앱의 기존 설정을 사용합니다.

사용 순서와 확인

  1. 현재 작업이 읽기·초안 작성인지, 실제 파일·서비스 변경인지 구분합니다.
  2. 승인 방식을 선택하고 적용 결과를 확인합니다. 지원되지 않는 정책은 오류를 확인하고 지원되는 선택으로 바꿉니다.
  3. 별도 앱·브라우저·운영체제 승인이 나오면 대상과 요청 동작을 읽고 결정합니다.

작업 승인 메뉴를 바꾸어도 다른 서비스의 계정 권한이나 앱 사용 동의가 자동으로 생기지는 않습니다. 도구별 실제 정책은 실행기와 조직 설정에 따라 다릅니다.

답변 일부를 인용해 수정 요청

어느 부분을 어떻게 고칠지 정확하게 지정합니다.

사용 순서
